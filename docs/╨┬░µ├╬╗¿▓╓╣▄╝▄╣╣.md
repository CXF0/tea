# 新版梦花仓管架构

## 1. 架构目标

新版梦花仓管不是按照“角色分别建设一套页面”，而是按照以下三条轴组织系统：

1. **业务领域**：入场、花材质检、配货、补货、打包、物流等业务能力独立建设。
2. **账户能力**：一个账户绑定一个角色，角色提供初始能力模板，账户最终能力决定能看到什么、能操作什么。
3. **统一工作台**：所有账户登录后进入同一个工作台，再根据配置动态组合工作台卡片、业务入口、待办和扫码能力。

最终目标：

- 新增角色以配置为主，不复制一套角色页面。
- 新增业务功能只影响所属领域。
- 同一个业务动作在不同入口复用同一组件、接口和数据记录。
- 页面入口、操作按钮和后端接口同时进行能力校验。
- 质检、配货、补货等跨领域状态拥有唯一事实来源。

## 2. 产品一级结构

所有账户登录后使用统一的四个一级入口。

### 2.1 工作台

工作台只由四部分组成：

#### 2.1.1 角色工作台卡片

- 位于快捷作业上方。
- 展示当前账户最重要的业务指标、场次状态和进度。
- 不同角色可配置不同卡片。
- 由 `workbenchCardIds` 控制。
- 示例：本场次任务、待质检数量、待配货数量、异常数量。

#### 2.1.2 快捷作业

- 是业务领域的入口集合。
- 展示哪些入口由账户可访问的业务领域决定。
- 由账户最终能力中 `wms_permission.permission_type = 1` 的领域入口权限控制。
- 示例：入场管理、花材质检、配货大厅、补货管理、质检任务。

#### 2.1.3 我的待办

- 聚合多个业务领域中与当前账户相关的待办事项。
- 由 `todoIds` 决定待办来源。
- 待办必须能够跳转到明确的业务对象和处理页面。
- 示例：待入场供应商、待质检货位、待配货货架、待提交补货单。

#### 2.1.4 扫码作业

- 工作台统一承载扫码入口，业务页面不再重复建设通用扫码按钮。
- 由 `scanOperationIds` 配置账户可用的扫码作业类型。
- 点击后先选择作业类型，再启动扫码。
- 示例：扫码质检、扫码配货、扫码打包、扫码入库、扫码发货。

### 2.2 数据中心

- 数据中心由公共数据卡片组成。
- 配置了什么数据卡片就展示什么，没有配置时展示空状态。
- 由 `dataCardIds` 控制。
- 数据卡片根据账户数据权限查询数据，不能只依靠前端隐藏。
- 示例：场次进度、质检问题分布、配货完成率、补货数量、库存概况。

### 2.3 消息中心

- 承载与当前账户相关的业务消息。
- 后续独立定义消息分类、触达方式、已读规则和跳转规则。
- 预计包含：任务通知、业务异常、审核结果、系统通知。

### 2.4 我的

- 个人资料。
- 账号与密码管理。
- 换绑手机号。
- 钱包与提现。
- 登录设备或安全能力。
- 退出登录。

## 3. 账户、角色与权限架构

### 3.1 基本原则

- 一个账户只绑定一个角色。
- 客户端不再提供角色切换。
- 角色不是页面集合，也不能决定一套独立前端。
- 角色是账户初始化时使用的能力模板。
- 登录会话返回的账户能力集合才是当前授权事实来源。

### 3.2 权限层级

```text
账户
  └─ 绑定一个角色
       └─ 角色引用一个或多个权限组
            └─ 权限组包含多个能力权限

账户还可进行能力增补或移除
最终有效能力 = 角色模板能力 + 账户增补 - 账户移除
```

### 3.3 权限对象

#### 角色

- 身份名称。
- 默认工作台配置。
- 初始业务领域。
- 初始权限组和能力集合。

#### 权限组

- 将相关能力组合为可复用授权单元。
- 示例：花材质检作业组、配货作业组、质检负责人管理组。

#### 能力权限

能力权限控制到具体操作，不只控制页面入口，例如：

```text
quality.view
quality.submit
quality.revoke
quality.itemControl
quality.statistics

distribution.view
distribution.allocate
distribution.cancelAllocation
distribution.markQualityIssue

restock.view
restock.submit
restock.history
```

#### 数据权限

数据权限决定账户可以处理的数据范围，例如：

- 指定仓库。
- 指定基地。
- 指定分区、分段。
- 指定场次。
- 指定供应商范围。
- 本人任务或本组任务。

### 3.4 前后端权限职责

- 前端根据能力隐藏或禁用入口和按钮，改善体验。
- 后端必须对每个受保护接口再次校验能力和数据范围。
- 前端隐藏不等于完成授权。

## 4. 公共业务领域

公共业务领域不是某个具体仓储环节，而是被多个领域和角色共同使用的业务能力。

### 4.1 场次

- 场次是仓内作业的主要时间上下文。
- 工作台统一切换当前场次。
- 切换后刷新工作台卡片、业务入口数据和待办。
- 场次不能简单等同于当前自然日期。

### 4.2 基础资料

- 仓库。
- 基地及基地简称。
- 供应商及供应商标签。
- 客户、收货人和手机号。
- 分区、分段、货架、货位。
- 花材品种、等级、成熟度和规格。
- 包装材料、周转容器等。

### 4.3 工作台卡片

- 统一卡片协议。
- 不同角色按配置组合。
- 卡片只负责摘要和跳转，不承载复杂业务操作。

### 4.4 数据卡片

- 数据中心使用的统一统计组件。
- 包含指标名称、数值、单位、统计口径、更新时间和跳转目标。
- 数据范围必须服从账户数据权限。

### 4.5 待办

- 各业务领域提供自己的待办来源。
- 工作台统一聚合和展示。
- 待办状态随真实业务状态变化，不单独维护一套重复状态。

### 4.6 扫码

- 统一扫码适配层。
- 扫码结果先识别对象类型，再路由到对应业务处理能力。
- 扫码成功不等于业务处理完成。
- 扫码作业分为供应商、花材、货架和包裹等对象类型，原始码统一解析后再进入所属领域。
- 工作台首批统一承载扫码入场、扫码质检、好花视频、扫码配货、扫码打包、扫码查发货、裸花暂存和退货确认。
- 基地退货连续扫码、冷库裸花补充登记等专用流程复用平台扫码能力，但状态提交仍由所属领域负责。

### 4.7 文件与凭证

- 图片和视频使用统一上传组件。
- 支持数量限制、上传进度、失败重试、预览和删除。
- 质检、判责、物流、发货等领域复用。

### 4.8 操作日志

- 记录业务对象、操作类型、操作人、时间、操作前后状态和备注。
- 撤销操作不能物理删除历史记录，应保留失效状态。

### 4.9 通用状态与反馈

- 加载中。
- 空数据。
- 请求失败。
- 无权限。
- 离线或弱网。
- 禁用及禁用原因。
- 提交中、防重复提交和成功反馈。

## 5. 业务领域划分

## 5.1 入场领域 `admission`

### 业务目标

管理供应商、基地或其他业务对象进入当前场次和仓库的过程。

### 主要功能

- 基地入场。
- 供应商签到和入场。
- 到场状态查询。
- 入场时间和操作人记录。
- 未入场、已入场、全部、有质检等筛选。

### 与花材质检的关系

- 入场管理是独立业务能力。
- 花材质检中的供应商列表也可以提供入场操作。
- 两个入口调用同一入场接口和状态，不建立重复数据。

## 5.2 集货领域 `collection`

### 业务目标

管理供应商花材的收集、到场确认和数量盘点。

### 主要功能

- 集货任务。
- 花材盘点。
- 到场数量确认。
- 基地、供应商和场次汇总。
- 集货异常记录。

## 5.3 花材质检领域 `quality`

### 业务目标

对场次供应商及其货架花材进行逐扎问题标记和处置。

### 页面层级

```text
场次供应商列表
  └─ 供应商花材/货架列表
       └─ 货架花材质检页面
            └─ 具体花材扎号
```

### 核心功能

- 供应商入场操作。
- 供应商花材列表。
- 货架花材逐扎选择。
- 质检问题类型选择。
- 处置方式选择。
- 处罚规则和处罚金额计算。
- 图片/视频质检凭证。
- 业务标记：商家全责、限制供应商自主配货、顾客不售后。
- 质检问题标记撤销。
- 操作日志。

### 质检标记处置方式

- 降一级。
- 降两级。
- 退货不补。
- 退货补货。
- 缺货补货。
- 缺货不补。
- 换货。

### 核心规则

- 正常花材不需要提交，质检只记录异常。
- 质检结果必须落到具体扎号、问题类型和处置方式。
- 花材业务状态与页面选中状态分开表达。
- 已有标记不能被下一次标记整体覆盖。
- 撤销只撤销质检标记，不撤销配货状态。
- 处罚规则区分供应商类型，包括是否斗南供应商。

## 5.4 质检任务领域 `quality-task`

### 业务目标

承载质检人员的专项任务，不等同于花材质检领域本身。

### 任务类型

#### 派发任务

- 管理员或负责人派发的货位质检任务。
- 展示已配货和未配货任务。
- 按货位或客户手机号搜索。
- 按客户类型和任务状态查询。

#### 自行货位检查

- 只展示花材质检产生的退货、换货标记汇总。
- 按货位聚合，同一货位可以同时包含退货和换货。
- 点击货位进入货架配货详情。
- 支持全部标记、退货、换货筛选。

#### 拍摄好花视频

- 扫描花材二维码。
- 拍摄并上传好花视频。
- 展示当日进度和拍摄记录。

## 5.5 配货领域 `distribution`

### 业务目标

按照客户订单和货架花材完成逐扎配货，并处理未配货异常。

### 配货大厅

- 待配货、配货完成两个主要状态。
- 普通仓/城市仓筛选。
- 自提筛选。
- 早班筛选。
- 待补筛选。
- 分区、分段筛选。
- 未配货汇总入口。
- 通用扫码入口不放在大厅，统一由工作台提供。

### 货架配货

- 一个货架可能包含多个供应商、多个花材和多个订单商品。
- 即使供应商、花材和品质相同，不同订单也必须拆分展示。
- 展示客户收货人和可拨打电话。
- 供应商前展示其真实基地简称。
- 展示逐扎待配、已配和质检问题状态。
- 支持确认配货和取消配货。
- 支持缺货/退货质检标记。
- 支持撤销质检标记。

### 质检标记复用原则

- 配货页不跳转到花材质检页面。
- 配货页复用质检标记抽屉组件。
- 调用同一质检问题、处罚预览、上传和提交接口。
- 产生同一份质检记录和操作日志。

### 未配货汇总

- 按分区筛选。
- 按订单号、花材名称查询。
- 汇总未配货数量。
- 支持缺货补货和缺货不补处置。

## 5.6 补货领域 `restock`

### 业务目标

根据缺货或退货形成的补货需求，匹配到场货库存并提交补货。

### 补货来源

- 缺货补货。
- 退货补货。
- 其他业务确认的场地补货需求。

### 主要功能

- 未补货和已补货列表。
- 列表多选后发起“我要补货”。
- 将所选需求带入待提交页面。
- 自动匹配到场货可补库存。
- 分列展示需补数量和到场库存。
- 支持手动提级、提一级和提半级等策略。
- 显示库存不足和实际可补数量。
- 提交补货单。
- 历史补货单查询。
- 历史单按场次、分区、流水号和状态查询。

### 核心规则

- 补货需求可能部分提交，不能用简单的“待提交”状态表达全部情况。
- 实际补货数量由提交当时的可补库存决定。
- 补货单必须具有场次内流水号。

## 5.7 冷库领域 `cold-storage`

- 花材暂存。
- 暂存位置和数量。
- 存入时间。
- 到期提醒。
- 出库操作。
- 暂存到期不等于已经出库。

已依据原仓管项目确认：

- 暂存分为包裹暂存和裸花暂存；裸花登记由花材二维码识别客户、场次、货位及原发货单，填写扎数并上传入库照片。
- 主页面分别查询待出库任务、已出库任务和仍在库库存，不能用计划日期或到期状态推导已经出库。
- 出库方式包括关联发货单、直接出库和转代卖；完成出库必须上传照片，转代卖还须填写不超过客服审批数量的最终出库扎数。
- 冷库库存 `xm_bulky_cold_stock` 是在库数量与状态的事实来源；`xm_bulky_cold_out_task` 是出库任务事实来源；包裹级状态由 `xm_bulky_cold_stock_package` 维护。

## 5.8 打包领域 `packing`

- 打包任务。
- 货架打包。
- 包花和装箱。
- 包装材料记录。
- 箱号、件数和复核。

## 5.9 物流领域 `logistics`

- 揽收。
- 发货。
- 物流人员分配。
- 物流拍照。
- 发货进度和异常。

## 5.9.1 兼职物流员领域 `part-logistics`

- 兼职物流员场次签到、工作中和收工记录。
- 按场次查看待分配与已分配人员。
- 批量分配管理组长，已收工人员不可再分配。
- 兼职工作记录 `xm_bulky_part_logistics` 是考勤、组长归属、工时和结算状态的事实来源。
- 物流发货领域只读取人员协作结果，不维护兼职人员工作状态。

## 5.10 运输领域 `transport`

- 司机与车队。
- 基地货量。
- 车辆配置。
- 装车和发车。
- 路线、起终点和运输异常。

## 5.11 库存领域 `inventory`

- 入库。
- 出库。
- 库存查询。
- 库存盘点。
- 物资申领。
- NFC 作业。
- 周转容器借还。

## 5.12 代卖领域 `consignment`

- 收购。
- 定级。
- 上架。
- 代卖库存。
- 代卖订单。

## 5.13 农资领域 `agri-material`

- 农资商品。
- 农资订单。
- 农资供应商。
- 商品标签。

## 5.14 管理领域 `management`

- 账户、角色、权限组和能力权限。
- 人员管理。
- 工作台配置。
- 统计配置。
- 处罚规则。
- 基础数据管理。
- 操作日志和审计。

## 5.15 账户领域 `account`

- 登录。
- 登录会话。
- 个人资料。
- 密码修改。
- 手机号换绑。
- 钱包和提现。
- 退出登录。

## 5.16 配货权限领域 `distribution-staff`

- 维护配货人员可操作分区，支持单人和批量配置。
- 人员与分区配置以旧系统 `xm_bulky_auth_user_role.perm_config.areaConfig` 为事实来源。
- 不承担账户、角色或配货业务状态管理。

## 5.17 质检人员假勤领域 `inspection-attendance`

- 查看质检人员出勤、休息状态并按姓名、ID、分区和状态筛选。
- 假勤事实来源为 `xm_bulky_inspection_assign_user.attendance_status`。
- 每次变更写入 `xm_bulky_inspection_attendance_log`，不覆盖或删除历史。

## 6. 主要业务链路

### 6.1 仓内主链路

```text
集货
  → 运输
  → 到场/入场
  → 花材盘点
  → 花材质检
  → 入库/上架
  → 配货
  → 包花/打包
  → 出库
  → 发货
```

### 6.2 异常链路

```text
花材质检发现异常
  ├─ 降级 → 修改花材等级并继续流转
  ├─ 退货不补 → 退回供应商，不产生补货需求
  ├─ 退货补货 → 退回供应商并产生补货需求
  ├─ 缺货不补 → 记录缺货，不产生补货需求
  ├─ 缺货补货 → 记录缺货并产生补货需求
  └─ 换货 → 进入换货处理流程
```

### 6.3 质检与配货协作

```text
花材扎号
  ├─ 质检标记状态：缺货/退货/换货/降级
  ├─ 配货状态：待配/已配
  └─ 页面选择状态：当前是否被操作人选中
```

三种状态相互独立：

- 质检标记不能覆盖配货状态。
- 配货或取消配货后应清除页面选择状态。
- 撤销质检标记不能撤销配货。
- 页面选中样式不能与业务状态样式混淆。

### 6.4 质检与补货协作

```text
质检标记为缺货补货或退货补货
  → 生成补货需求
  → 补货管理选择需求
  → 匹配当前到场货可补库存
  → 确认补货策略
  → 提交补货单
```

## 12. 数据与安全原则

- 本地开发使用独立数据库，不能影响原测试库和生产库。

## 14. 当前架构结论

```text
所有账户进入统一工作台
  → 角色提供初始配置
  → 账户能力决定可见领域和可执行操作
  → 工作台组合卡片、入口、待办和扫码能力
  → 业务页面归属于领域，而不归属于角色
  → 跨领域复用组件、接口和同一业务记录
```

新版梦花仓管最终应做到：

- **新增一种角色，主要修改配置。**
- **新增一项业务，主要修改对应领域。**
- **接口字段变化，主要影响 API、Mapper 和模型层。**
- **扫码、上传、打印、NFC 等平台能力只维护一份。**
- **同一业务状态只有一个事实来源。**
- **不同角色可以组合多个业务领域，但不会产生角色专属页面副本。**

## 15. 领域边界与事实来源矩阵

| 业务对象或状态 | 事实来源领域 | 其他领域如何使用 | 禁止做法 |
|---|---|---|---|
| 供应商是否入场 | 入场 | 花材质检、集货读取并可复用入场操作组件 | 在质检领域另建一套入场状态 |
| 花材到场与盘点数量 | 集货 | 质检、库存、补货读取 | 各页面自行维护到场数量 |
| 具体扎号的质检问题 | 花材质检 | 配货、补货、质检任务读取或调用统一标记组件 | 配货页另存一份“缺货/退货”状态 |
| 扎号配货状态 | 配货 | 质检、打包、未配货汇总读取 | 质检标记自动覆盖配货状态 |
| 补货需求 | 补货 | 由质检处置或配货异常触发，配货读取进度 | 用列表展示状态代替真实补货需求记录 |
| 冷库暂存状态 | 冷库 | 质检、库存读取 | 把暂存到期直接视为出库 |
| 打包状态 | 打包 | 物流、发货读取 | 配货完成自动视为打包完成 |
| 发货状态 | 物流 | 工作台、消息中心读取 | 扫码成功自动视为发货完成 |
| 账户能力 | 账户与权限 | 所有领域用于页面、按钮和接口授权 | 仅依靠前端隐藏入口 |
| 基础资料 | 公共基础数据 | 所有业务领域引用 | 在业务表中重复维护基地、分区等配置 |

### 边界判断方法

遇到跨领域功能时，按以下顺序判断：

1. 当前操作实际改变的是哪个业务对象？
2. 哪个领域拥有该对象的状态和业务规则？
3. 当前页面是该能力的主入口，还是另一个便捷入口？
4. 若只是便捷入口，应复用所属领域的组件、服务、接口和记录。
5. 跨领域页面不得复制一套相似状态或提交逻辑。

例如，配货页面中的“缺货/退货标记”改变的是质检问题记录，因此页面可以提供入口，但必须复用花材质检领域的标记组件和接口；“确认配货”改变的是配货状态，仍归配货领域负责。

## 16. 统一工作台配置模型

### 16.1 账户最终工作台配置

```ts
interface AccountWorkbenchProfile {
  accountId: number
  roleId: number
  workbenchCardIds: string[]
  todoIds: string[]
  scanOperationIds: string[]
  dataCardIds: string[]
  capabilities: string[]
  dataScopes: DataScope[]
}
```

### 16.2 配置职责

| 配置项 | 决定什么 | 不负责什么 |
|---|---|---|
| `workbenchCardIds` | 快捷作业上方展示哪些角色核心卡片 | 不决定数据中心内容 |
| `todoIds` | 工作台聚合哪些待办来源 | 不另建待办业务状态 |
| `scanOperationIds` | 扫码入口支持哪些作业类型 | 不代表扫码后有提交权限 |
| `dataCardIds` | 数据中心展示哪些公共数据卡片 | 不突破账户数据权限 |
| `capabilities` | 页面、按钮和接口允许执行哪些操作 | 不决定数据可见范围 |
| `dataScopes` | 可访问仓库、基地、分区、场次等范围 | 不替代操作能力校验 |

### 16.3 工作台生成过程

```text
登录成功
  → 后端返回账户、唯一角色、能力集合和数据范围
  → 加载账户工作台配置；没有账户覆盖时使用角色模板
  → 生成角色核心卡片
  → 按最终能力中的领域入口权限生成快捷作业入口
  → 按待办来源聚合我的待办
  → 按扫码能力生成扫码作业类型
  → 数据中心按 dataCardIds 独立生成数据卡片
```

### 16.4 角色与账户配置关系

- 角色配置是新账户的初始化模板。
- 账户可以在角色模板基础上增补或移除能力。
- 账户登录后不切换角色。
- 同一角色下不同账户可以因能力或数据范围不同而拥有不同工作台。
- `wms_permission` 使用 `parent_id` 组织权限树，`permission_type=1` 表示领域入口，`permission_type=2` 表示领域功能权限。
- 领域功能权限不自动授予领域入口；跨领域页面可只获得所需功能权限。

## 17. 已确定事项与待继续梳理事项

### 17.1 已确定

- 产品名称为“梦花仓管”。
- 前端采用 Vue 3 + uni-app，H5 作为当前主要开发预览环境。
- 所有账户使用统一工作台和统一底部导航。
- 一个账户绑定一个角色，不提供角色切换。
- 角色是能力和工作台配置模板，不是独立页面集合。
- 快捷作业是业务领域入口。
- 工作台顶部卡片、快捷作业、我的待办、扫码能力分别配置。
- 数据中心只展示已配置的数据卡片。
- 入场管理是独立领域能力，也可以在花材质检入口复用。
- “质检”领域对用户统一命名为“花材质检”。
- 花材质检按场次供应商 → 供应商花材 → 货架逐扎操作组织。
- 正常花材无需操作，质检主要记录异常。
- 质检问题必须落到具体扎号、问题类型和处置方式。
- 配货必须按订单商品拆分，即使供应商和花材属性相同。
- 配货状态、质检标记状态和当前选择状态相互独立。
- 配货页的质检标记复用质检组件和接口，不跳转质检页面。
- 通用扫码能力统一放在工作台，业务大厅不重复建设。
- UI 使用松青白配色和统一的线性图标体系。

### 17.2 已建立框架、仍需逐模块核对原业务

- 集货和花材盘点的完整作业步骤。
- 冷库暂存的入库、到期和出库规则。
- 打包、包花、装箱和复核的业务对象关系。
- 物流揽收、人员分配、拍照和发货的完整链路。
- 库存、物资申领、NFC 和周转容器规则。
- 代卖、农资和运输领域的详细页面与状态机。
- 消息中心的消息分类、触发条件、已读和跳转规则。
- 钱包、提现及财务审核流程。

这些模块在设计和开发前，必须先检查旧项目的对应页面、接口和数据库结构，确认真实业务后再形成新版方案，不能仅根据领域名称推测。

### 17.3 仍需统一定义的系统级规则

- 场次的创建、切换、关闭和跨日规则。
- 工作台卡片、待办和数据卡片的注册协议。
- 权限组与账户能力覆盖的冲突优先级。
- 数据权限的组合方式和查询层实现。
- 跨领域事件是同步调用还是异步事件。
- 操作日志保留周期和审计查询权限。
- 图片、视频的存储、压缩、时长、大小和清理策略。
- 弱网、离线草稿和失败重试范围。
- 金额、处罚、钱包等财务相关操作的审核和幂等规则。
