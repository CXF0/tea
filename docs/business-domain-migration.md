## 公共领域

- 工作台卡片：按账户角色配置，不归属具体角色页面。
- 数据卡片：作为数据中心的可配置公共组件。
- 待办：聚合各业务域的可处理任务，只展示用户拥有能力的项目。
- 扫码：统一解析二维码后，再路由到被授权的业务动作。
- 消息：承载与本人相关的业务消息，后续单独定义消息类型和已读规则。
- 设备能力：扫码、NFC、蓝牙打印、图片上传通过平台适配层调用。

`admission` 是跨角色共享作业域，不属于质检。质检员、质检负责人和基地入场员复用同一套入场页面，通过 `admission.*` 能力控制查看、确认、扫码、历史、统计和异常处理。

`admission` 独立不代表其他业务页面不能执行入场动作。花材质检的场次供应商列表复用入场状态接口；领域归属按页面主要任务划分，跨领域动作按能力授权复用。

花材质检采用异常标记制：正常花材无需提交；发现问题时记录“具体花材扎号 + 一个或多个质检问题类型 + 处置方式”。列表只汇总是否存在问题标记，问题来自质检原因配置，处置方式独立记录。

## 实施约束

1. 页面按业务域归属，角色仅配置能力、入口、卡片和待办。
2. 页面不得直接依赖旧项目接口封装；接口先进入 Domain API，再经 Service 转为页面模型。
3. 同一任务状态必须由后端校验，前端提交后重新读取，防止重复处理。
4. 每个领域按“列表/入口 → 详情 → 主操作 → 结果反馈 → 返回刷新”完成闭环后再迁移下一个领域。
5. 供应商相关接口变更前核对旧项目 `AGENTS.md` 指定的 Knife4j 文档，并同步维护 API 文档。

## 推荐迁移顺序

质检 → 配货 → 打包 → 补货 → 物流 → 入场 → 库存 → 运输 → 代卖/农资 → 管理。
